# 关西可核验行程：用户视角走查

## 能完成的任务

- 从首页生成行程，进入规划器，逐日调整、保存、刷新后继续编辑，也可从个人中心打开。
- 在手机尺寸下为成人团填出发日期和门票上限，识别大阪城天守阁 17:45 的最晚入场冲突，修改第一天的时间，不改动第二天。
- 打印视图展示所有天，而不是只打印当前选中的一天。保存 PDF 时会带上当前版本的入场冲突、待核实项、门票小计与官方资料；修改后未重查则会明确提示，不沿用旧结果。读取已保存行程失败时不再显示可覆盖原数据的示例编辑器。

## 上线之前我会优先补的三件事

1. **把提示连到可操作的下一步。** 点异常跳到当天对应景点；让用户能选择候选地点，避免 AI 使用「大阪城打卡」等复合文字时无法匹配。接着补齐一条真正完整的关西路线所需的景点、交通时间与计划 B，而不是追求覆盖城市数量。
2. **让旅行当天也能打开。** 现在可以存 PDF，但网站本身仍加载 CDN 脚本。下一步做真正的离线只读行程、逐站导航和手机端验收；线路链接不等于实时交通校验。
3. **再考虑通用日程。** 可把日期、待办、预算和「待核实」状态复用到周末活动、展会或学习计划。先让真实用户完成一次旅行规划，再考虑把这些能力拆成独立模板；暂不扩张成社区或万能问答。

当前不是实时旅游数据库，也不是对外多用户服务。公开部署前需要身份与数据隔离、访问限制、运维和隐私检查。
